# RetailFlow Import References

## 图片 / 扫描件
- 只引用图片中真实可见内容。
- 若图片模糊、遮挡、压缩严重，必须明确说明无法可靠识别。
- 禁止使用“模拟视觉识别”“假设识别”“推测图片内容”等表述。
- 图片输出只是候选字段，不代表已经匹配系统主数据。

## 主体解析
- 供应商只和供应商主数据匹配。
- 客户只和客户主数据匹配。
- 如主体不存在、歧义或低置信度，应先追问用户，不要先调写工具。

推荐追问模板
- 系统中没有识别到该供应商。您要新建供应商，还是映射到已有供应商？
- 系统中没有识别到该客户。您要新建客户，还是映射到已有客户？

## 商品解析
- 商品名称与 SKU 只作为候选匹配依据，不代表已经命中库存主数据。
- 当图片里的商品在系统中未命中时，优先追问是否新建商品档案，或映射到已有商品。

推荐追问模板
- 以下商品未匹配到系统商品：A、B、C。您要新建这些商品，还是逐项映射到已有商品？

## 追问顺序
- 由模型自主判断，不靠代码写死顺序。
- 判断原则：
  - 用户提示词已经明确采购或销售方向时，直接沿用户方向继续，不要重复追问单据类型。
  - 单据类型不明确且会影响业务流向时，先问采购单还是销售单。
  - 单据类型明确但主数据缺失时，先问新建还是映射。
  - 如果多个问题同时存在，先问最阻塞后续执行的那个问题。
- 不要把“识别出了哪些商品”误当成可点击选项。
- interruption 里的 options 必须是动作，不是证据列表。

## 文档
- 优先提取单据抬头、编号、日期、往来方、明细表头、金额与备注。
- 缺关键字段时先返回识别结果和缺口，不直接写入。

## 表格
- 优先识别表头与行结构。
- 列映射不确定时先返回候选映射，而不是直接建单。
